# Занятие 2. Многопоточный сервер для множества клиентов

## Цель занятия

Научиться создавать сервер, который может одновременно обслуживать несколько клиентов. Для этого мы используем модуль `threading` – каждый клиент будет обрабатываться в отдельном потоке. Также добавим логирование подключений и отключений. В результате у нас будет многопоточный эхо-сервер, способный параллельно работать с любым количеством клиентов.

---

## Теоретическая часть

### Проблема блокировки

В прошлом занятии наш сервер после вызова `accept()` ждал подключения, а затем входил в бесконечный цикл `while True`, обрабатывая одного клиента. Пока этот клиент не отключался, сервер не мог принять новых клиентов.

**Решение:** выделять для каждого подключения отдельный поток. Пока один поток общается с клиентом, главный поток может спокойно принимать новых.

### Модуль threading

Поток (thread) – это легковесный процесс, который выполняется параллельно с другими потоками внутри одной программы.

Основные возможности:
```python
import threading

def worker():
    print("Я работаю в потоке")

t = threading.Thread(target=worker, args=())
t.start()   # запуск потока
t.join()    # ожидание завершения потока (необязательно)
```

### Структура многопоточного сервера

1. **Главный поток**:
   - Создаёт сокет, привязывает, начинает слушать.
   - В бесконечном цикле вызывает `accept()`.
   - Для каждого нового клиента создаёт поток-обработчик.

2. **Поток-обработчик** (handler):
   - Получает сокет клиента.
   - Внутри цикла читает данные и отправляет обратно (эхо).
   - При отключении клиента закрывает сокет и завершается.

### Синхронизация доступа к общим ресурсам (Lock)

В будущем нам понадобится общий список клиентов или разделяемая переменная. Если несколько потоков одновременно изменяют один и тот же объект, могут возникнуть ошибки (race condition). Для синхронизации используется `threading.Lock`:
```python
lock = threading.Lock()
lock.acquire()
# критическая секция
lock.release()
```
или более удобный контекстный менеджер:
```python
with lock:
    # критическая секция
```

Сегодня мы используем блокировку для безопасного вывода в консоль (логирования) – чтобы сообщения от разных потоков не перемешивались.

### Логирование

Вместо `print` лучше использовать модуль `logging`, который предоставляет уровни логирования, временные метки и безопасный вывод. Однако для простоты можно обойтись `print` с блокировкой. Но мы покажем оба подхода.

## Практика: многопоточный эхо-сервер

### Пошаговая разработка

1. **Импорты**:
   ```python
   import socket
   import threading
   import logging
   ```

2. **Настройка логирования**:
   ```python
   logging.basicConfig(level=logging.INFO, format='%(asctime)s - %(levelname)s - %(message)s')
   ```

3. **Функция-обработчик клиента**:
   ```python
   def handle_client(client_socket, client_address):
       logging.info(f"Новое подключение: {client_address}")
       try:
           while True:
               data = client_socket.recv(1024)
               if not data:
                   break
               logging.debug(f"Получено от {client_address}: {data[:50]}...")
               client_socket.send(data)   # эхо
       except ConnectionResetError:
           logging.warning(f"Клиент {client_address} оборвал соединение")
       finally:
           client_socket.close()
           logging.info(f"Клиент {client_address} отключился")
   ```

4. **Основной серверный цикл**:
   ```python
   def main():
       HOST = '127.0.0.1'
       PORT = 12345

       server_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
       server_socket.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
       server_socket.bind((HOST, PORT))
       server_socket.listen(5)
       logging.info(f"Сервер запущен на {HOST}:{PORT}")

       try:
           while True:
               client_socket, client_addr = server_socket.accept()
               # Создаём поток для нового клиента
               thread = threading.Thread(target=handle_client, args=(client_socket, client_addr))
               thread.start()
               logging.debug(f"Активных потоков: {threading.active_count() - 1}")
       except KeyboardInterrupt:
           logging.info("Сервер остановлен пользователем")
       finally:
           server_socket.close()
   ```

### Полный код многопоточного эхо-сервера (`multi_echo_server.py`)

```python
import socket
import threading
import logging

# Настройка логирования
logging.basicConfig(
    level=logging.INFO,
    format='%(asctime)s - %(levelname)s - %(message)s',
    datefmt='%H:%M:%S'
)

def handle_client(client_socket, client_address):
    """Обрабатывает одного клиента: принимает данные и отправляет обратно."""
    logging.info(f"Клиент {client_address} подключился")
    try:
        while True:
            data = client_socket.recv(1024)
            if not data:
                break
            logging.info(f"Эхо для {client_address}: {data.decode('utf-8')}")
            client_socket.send(data)
    except ConnectionResetError:
        logging.warning(f"Клиент {client_address} неожиданно разорвал соединение")
    except Exception as e:
        logging.error(f"Ошибка при обработке {client_address}: {e}")
    finally:
        client_socket.close()
        logging.info(f"Клиент {client_address} отключился")

def main():
    HOST = '127.0.0.1'
    PORT = 12345

    server_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    server_socket.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    server_socket.bind((HOST, PORT))
    server_socket.listen(5)
    logging.info(f"Многопоточный эхо-сервер запущен на {HOST}:{PORT}")

    try:
        while True:
            client_socket, client_addr = server_socket.accept()
            thread = threading.Thread(target=handle_client, args=(client_socket, client_addr))
            thread.start()
            logging.debug(f"Активных потоков: {threading.active_count() - 1}")
    except KeyboardInterrupt:
        logging.info("Получен сигнал остановки, завершаем работу...")
    finally:
        server_socket.close()

if __name__ == "__main__":
    main()
```

## Клиент для тестирования

Клиент может остаться таким же, как в прошлом занятии (`echo_client.py`). Но теперь мы можем запустить несколько экземпляров клиента одновременно, и сервер обработает всех.

Для удобства тестирования можно создать упрощённого клиента, который автоматически отправляет несколько сообщений и завершается. Вот такой:

```python
# test_client.py
import socket
import time

def main():
    HOST = '127.0.0.1'
    PORT = 12345

    client = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    client.connect((HOST, PORT))
    print("Подключено к серверу")

    for i in range(3):
        msg = f"Сообщение {i+1} от тестового клиента"
        client.send(msg.encode())
        response = client.recv(1024)
        print(f"Ответ: {response.decode()}")
        time.sleep(1)

    client.close()
    print("Клиент завершил работу")

if __name__ == "__main__":
    main()
```

## Логирование с блокировкой (альтернативный вариант)

Если вы хотите использовать `print` и быть уверенными, что вывод не перемешается, можно добавить мьютекс:

```python
print_lock = threading.Lock()

def safe_print(*args, **kwargs):
    with print_lock:
        print(*args, **kwargs)
```

Тогда в `handle_client` вместо `print` вызываем `safe_print`. Однако модуль `logging` уже потокобезопасен, поэтому мы используем его.

## Разбор кода и типичные ошибки

### Потоки не завершаются после отключения клиента
В нашем коде поток завершается, когда выходим из `handle_client` (после закрытия сокета). Однако если в `recv` возникнет исключение, мы его перехватываем и корректно закрываем сокет. Поток автоматически удаляется после завершения функции.

### Утечка потоков
При активной работе сервера количество потоков равно количеству клиентов. Это нормально для демонстрации, но в реальном проекте стоит ограничивать число потоков (например, пулом потоков). Пока оставим как есть.

### Исключение `ConnectionResetError`
Возникает, если клиент закрыл соединение неожиданно (например, программа вылетела). Мы обрабатываем его отдельно.

### Активных потоков больше, чем клиентов
`threading.active_count()` включает главный поток, поэтому вычитаем 1. Также могут быть внутренние потоки (например, для `logging`), но обычно их нет.

### Зависание при остановке сервера
Если во время остановки сервера какие-то потоки всё ещё выполняют `recv`, они могут заблокироваться. Мы установили `try/except KeyboardInterrupt`, но в дочерних потоках `recv` не прерывается. Это приемлемо для учебного примера. Позже мы добавим механизм graceful shutdown.
